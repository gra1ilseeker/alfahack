# MVP-план: аналитический дашборд + ранжирование продуктов

## 1. Границы MVP
- **Цель**: показать ценность умного кабинета через персонализированный дашборд и рекомендацию кредитных продуктов.
- **Функциональность**:
  1. Онбординг клиента с вводом ключевых метрик (ручной ввод + .csv).
  2. Дашборд «Здоровье бизнеса» (выручка, маржинальность, денежный поток, индекс устойчивости).
  3. Интерактивные подсказки ассистента на основе аналитики.
  4. Ранжирование кредитных продуктов логистической регрессией + объяснения факторов.
  5. Страница продукта с коротким описанием, ключевыми условиями и CTA «подать заявку» (заглушка).

## 2. Данные и интеграции
- **MVP-источники**: 
  - CSV-шаблон финансовых показателей (месячный оборот, расходы, доля онлайн-продаж).
  - Ручной ввод целей финансирования и текущих кредитов.
  - Моковый каталог продуктов банка (JSON).
- **Интеграции в перспективе**: коннекторы к бухгалтерии/маркетплейсам (описать интерфейсы, но не реализовывать).
- **Фиче-стор**: простая реализация (pandas + SQLite) для хранения профилей и признаков модели.

## 3. Архитектура
```mermaid
flowchart LR
    UI[Web UI (React/Vue)] --> API[Backend API (FastAPI)]
    API --> Store[SQLite Feature Store]
    API --> MLService[Logistic Regression Service]
    MLService --> Store
    API --> Dashboard[Analytics Engine]
```
- **Фронтенд**: SPA с модулями онбординга, дашборда, Product Matchmaker.
- **Бэкенд**: FastAPI + SQLAlchemy; эндпоинты /profile, /dashboard, /rank-products.
- **ML-сервис**: Python sklearn, модель хранится как pickle, REST/gRPC слой.
- **Аналитика**: модуль расчёта индекса устойчивости и прогнозов (простые эвристики + ARIMA/Prophet позже).

## 4. Поэтапный план
1. **Спринт 0**: утвердить макеты, подготовить моковые данные, описать API.
2. **Спринт 1**: реализовать онбординг (форма, загрузка CSV), создать feature store.
3. **Спринт 2**: построить дашборд (backend расчёты + UI визуализации), встраивание подсказок ассистента (rule-based).
4. **Спринт 3**: обучить простую логистическую модель (синтетические/исторические данные), поднять сервис ранжирования.
5. **Спринт 4**: интегрировать ранжирование в UI, добавить объяснения факторов, обвязать CTA.
6. **Спринт 5**: полировка, демонстрационный сценарий, метрики и логирование.

## 5. Риски и меры
- **Недостаток данных** → использовать синтетические кейсы, предусмотреть быстрое подключение новых источников.
- **Сложность UX** → показать короткий guided tour и шаблонные советы.
- **Модель переобучается** → регуляризация, удержание простых признаков, ручная валидация кейсов.
- **Трудность объяснения** → встроенный блок объяснимости (топ-коэффициенты, графики влияния).

## 6. Метрики демонстрации
- Время от онбординга до получения рекомендаций < 2 минуты.
- Минимум 3 продукта в выдаче, каждый со скором и причинами.
- Пользователь видит минимум 4 ключевые метрики на дашборде + одну подсказку ассистента.
- Наличие лога действий для showcasing.
