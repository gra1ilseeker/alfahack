# Логистическая регрессия для ранжирования кредитных продуктов

## 1. Цель и место в архитектуре
- **Назначение**: оценивать вероятность того, что конкретный кредитный продукт будет оптимальным для клиента по сочетанию одобрения, стоимости и соответствия бизнес-целям.
- **Использование**: модель выдаёт скор, который питает модуль Product Matchmaker within credit lab; ассистент объясняет выбор пользователю.
- **Результат**: ранжированный список продуктов (овердрафт, факторинг, оборотный кредит, лизинг, госпрограммы) с объяснимыми причинами.

## 2. Данные и признаки
1. **Бизнес-профиль**: отрасль, выручка, сезонность, доля безнал/нал, структура расходов, маржинальность.
2. **Цели финансирования**: пополнение оборотного капитала, оборудование, маркетинг, растущие контракты.
3. **Кредитная история**: текущая долговая нагрузка, просрочки, наличие залогов.
4. **Поведение в кабинете**: сценарии симуляций, выбранные параметры (сумма, срок, график).
5. **Продуктовые характеристики**: лимит, ставка, требования к залогу, скорость выдачи, господдержка.
6. **Контекст**: макро- и отраслевые индексы, сезонные пики, участие в программах поддержки.
- **Источники**: банковские системы, подключённые бухгалтерии, маркетплейсы, CRM, внешние API (государственные реестры).
- **Обогащение**: one-hot по категориям, нормализация сумм, взаимодействия (interaction terms) по цели и продукту.

## 3. Пайплайн обучения и скоринга
- **Label**: бинарный признак успешного матча (клиент выбрал продукт и получил одобрение / клиент доволен условиями).
- **Train pipeline**: сбор исторических заявок, фиче-инжиниринг, балансировка классов (SMOTE/weights), кросс-валидация.
- **Регуляризация**: L1/L2 для интерпретируемости, контроль мультиколлинеарности.
- **Explainability**: коэффициенты модели, SHAP/ICE для ассистента.
- **Online scoring**: real-time API, принимает профиль клиента и список доступных продуктов, возвращает скор и топ-N.
- **Feedback loop**: логирование откликов, A/B тесты разных feature sets.

## 4. Интеграция с кредитной лабораторией
1. **DataHub** подготавливает признаки и масштабирует их в фиче-сторе.
2. **Product Matchmaker** обращается к сервису логистической регрессии для ранжирования.
3. **ИИ-ассистент** визуализирует топ рекомендаций, объясняет ключевые факторы и предлагает альтернативы.
4. **Negotiation Navigator** использует скор как вход для моделирования переговоров.
5. **Совместный режим**: менеджеры банка видят те же ранги с комментариями.

## 5. Контроль качества и метрики
- **Модельные метрики**: ROC-AUC, PR-AUC, логистическая потеря, калибровка.
- **Бизнес-метрики**: конверсия в одобрение, NPS выбора продукта, время до решения, маржа.
- **Мониторинг**: дрифт признаков, стабильность коэффициентов, fairness (отраслевые/региональные разрезы).
- **Эксперименты**: тесты ассистента, где модель включена/отключена, оценка влияния на воронку.

## 6. План внедрения
1. Сформировать датасет исторических матчей клиент-продукт.
2. Выстроить фиче-стор и ETL для признаков.
3. Обучить/валидацию модели логистической регрессии, настроить регуляризацию.
4. Подготовить сервис скоринга (REST/gRPC) и механизмы explainability.
5. Интегрировать с кредитной лабораторией и ассистентом, провести A/B тесты.
6. Настроить мониторинг, алерты и периодический retrain.
